# 微博舆情分析

一键完成微博舆情分析全流程：爬取评论 → 情感分类 → 话题聚类 → 生成 markdown 分析报告。

**触发方式**：用户输入"分析X月Y日的舆情"或"分析{账号}X月Y日的舆情"。

## 默认配置

- **默认账号**：广州天气
  - user_id: `2294193132`
  - 如果用户指定了其他账号名，需要用户提供对应的 user_id
- **输出目录**：`舆情分析/{微博用户名}/`
- **输出文件**：`{微博用户名}_{YYYYMMDD}.md`

## 执行流程

按顺序执行以下步骤，前一步成功才进入下一步，任一步失败则终止并报错。

**架构说明**：本技能是编排层，不重复描述各子技能的执行细节。第二步引用 `weibo-comment-scraper`，第三步引用 `weibo-sentiment-classifier`，第四步引用 `weibo-topic-clusterer`。详细命令和参数见各自 skill 文档。

### 第一步：解析用户输入

从用户提示词中提取：

1. **日期**：`X月Y日` → 补全为当年日期 `YYYY-MM-DD`
   - 如 "5月20日" + 当前年2026 → `2026-05-20`
2. **账号**：如果用户指定了账号名，使用指定账号；否则使用默认"广州天气"
   - 如果是新账号，记录下 user_id 以便后续复用
3. **时间范围**（默认规则）：
   - 一天的定义为 **当日 08:00 至次日 08:00**
   - start_time: `YYYY-MM-DD 08:00`
   - end_time: `YYYY-MM-DD + 1天 08:00`（次日 08:00）
   - 如 "5月20日" → `2026-05-20 08:00` 至 `2026-05-21 08:00`
   - 如果用户明确指定了具体时间（如"5月20日0点到24点"），则以用户指定的为准

### 第二步：爬取评论

按照 `.claude/skills/weibo-comment-scraper/skill.md` 的「时间范围模式」执行。

参数：`--user-id {user_id} --start "{start_time}" --end "{end_time}"`

输出：JSON 文件路径列表。

### 第三步：情感分类

按照 `.claude/skills/weibo-sentiment-classifier/SKILL.md` 的工作流程执行。

参数：`--input "{第二步的JSON文件路径}"`

对每个 JSON 文件逐个处理。输出：EXCEL 文件路径列表及其分类统计。

### 第四步：话题聚类

按照 `.claude/skills/weibo-topic-clusterer/skill.md` 的分析流程执行。

参数：全部 JSON + 全部 EXCEL，`--max-comments 200 --format text`

输出：结构化话题分析结果（话题名、提及次数、情感倾向、代表评论）。

### 第五步：计算补充统计数据

使用 `compute_stats.py` 脚本一次性计算所有统计数据：

```bash
cd MediaCrawler
uv run python ../.claude/skills/weibo-opinion-analyzer/scripts/compute_stats.py \
    --input "{第二步输出的JSON文件1}" \
    --input "{第二步输出的JSON文件2}" \
    --sentiment "{第三步输出的EXCEL文件1}" \
    --sentiment "{第三步输出的EXCEL文件2}" \
    --top-n 3
```

脚本输出 JSON，包含：
- `global_stats`：微博数量、总评论数、总点赞数、总转发数、有效评论数
- `top_posts`：TOP3 热门帖子（含热度指数 = 评论数×0.4 + 点赞数×0.3 + 转发数×0.3，情感分布，代表评论）
- `sentiment_distribution`：正面/负面/中性数量及占比
- `representative_comments`：供话题聚类使用的采样评论

### 第六步：生成 Markdown 报告

按模板 `reference/report_template.md` 生成报告，写入 `舆情分析/{微博用户名}/{微博用户名}_{YYYYMMDD}.md`。

### 报告生成注意事项

1. **帖子标题提取**：取 `note_text` 的前 50 个字符作为标题，去除换行符
2. **情感分布百分比**：保留一位小数，三类之和应为 100%
3. **代表评论**：选择点赞数较高、内容有实质信息的评论
4. **话题内容**：核心关切话题直接嵌入第四步的输出，不要重新生成
5. **TOP3 用户反馈**：结合该帖子的情感分类结果描述，如"正面为主（约65%）"
6. **TOP3 主要话题**：从该帖子评论中高频词归纳，1-2句话概括

### 目录结构确认

生成报告前，确保目录存在：
```
舆情分析/
└── {微博用户名}/
    └── {微博用户名}_{YYYYMMDD}.md
```

如果目录不存在，先创建。

## 验证码处理

爬取过程中如果遇到微博验证码（API 返回 `errno: -100` 或输出含 `captcha`），按以下流程处理：

1. **立即停止**当前爬取，告知用户"微博触发了验证码保护，等待 5-10 分钟后自动重试"
2. **等待 300-600 秒**（5-10分钟），让验证码冷却过期
3. **自动重试**：重试时降低请求频率，分两批爬取：
   - 第一批：`--max-notes 100`，常规间隔
   - 如果第一批未覆盖目标日期，等待 30 秒后跑第二批：`--max-notes 200`，`crawl_interval` 调整为 2 秒
4. 重试仍失败则终止，提示用户"验证码仍未解除，建议等待更长时间后手动重试"

**预防策略**：
- 默认 `--max-notes 100`，先尝试覆盖目标日期
- 单次请求量不足时逐步加大，避免一次性请求过多触发风控
- 天气类账号发帖频繁（日均 3-10 条），100 条覆盖约 10-30 天

## 错误处理

| 场景 | 处理方式 |
|---|---|
| 该日期无帖子 | 提示"该日期（{date}）账号 @{name} 未发布任何微博" |
| Cookie 失效 | 提示"微博 Cookie 已过期，请更新 .weibo_cookies 文件后重试" |
| 无评论数据 | 跳过情感分类和话题聚类，报告仅输出数据概览 |
| 评论量过大（>5000条） | 话题聚类时随机采样2000条，报告中注明采样方式 |
| 触发验证码 | 遵循上方「验证码处理」流程：停止→等待5-10分钟→自动重试 |

## 指定其他账号

用户可以在提示词中指定账号：
- "分析广州日报5月20日的舆情" → 需要用户提供 user_id
- 首次使用新账号时，询问用户提供 user_id，并记录到本次会话中
- 后续可考虑建立账号-user_id 映射表
